## Why

`behdslabs` is a fork of Irizarry & Gill's `dslabs` package (29 datasets: US murders, elections, olive oil, movies, breast cancer, etc.). The course it supports — *Behavioural Data Science* (PS3140, Cognitive Science for Human-Centric Technologies) — is about behavioural data with a focus on digital technologies, apps, wearables, and neurophysiological methods. This plan reflavors the package's examples to match: same numbers (unchanged, or linearly rescaled only where needed for a plausible range), new names/framing so every example reads as an app/wearable/neuro scenario.

This is an **interim step**. It is not synthetic or real behavioural data — see the disclaimer rule below. A fully synthetic `bdslabs` dataset set (RT/accuracy/Likert/longitudinal constructs) is a separate, later phase (`BDS_development_plan.md` Phase 2).

## Ground rules

1. **Additive, non-destructive.** Original datasets (`murders`, `heights`, `gapminder`, etc.) are never modified or deleted. New reflavored datasets are added as new objects, coexisting in the same package. This is deliberate: the two book repos (`behdsbook-part-1`, `behdsbook-part-2`) reference the old dataset names in 60+ places, so nothing there breaks. Retiring the old names is a distinct future step (`BDS_development_plan.md` Phase 3, book adaptation) — not part of this plan.
2. **Disclaimer everywhere.** Every reflavored dataset's roxygen doc (`R/<name>.R`) carries a `@note` explaining it's relabeled/rescaled `dslabs` data, not real behavioural data. The same disclaimer is echoed once in `DESCRIPTION` and `README.md`.
3. **Numeric values must differ from the originals, by a documented rule, enforced by tests.** Every reflavoured numeric column is a deterministic transform of its `dslabs` source and must not be byte-identical to it. The default is multiplicative: `new = k * old`, one constant `k ≠ 1` per column, defined in `R/reflavor_constants.R` (`.reflavor_k`); count columns are wrapped in `round()`. Columns that stay byte-identical — because a multiplicative shift would break their meaning — are: dates/timestamps/`year`; ID and weight columns; proportions/probabilities bounded to [0,1] or [0,100]; compositional columns that must sum to ~100; opaque pixel/feature matrices; free text. Two columns use a linear range-rescale instead of a multiplier (`reaction_times$rt_ms` → 200–500 ms, `global_tech_adoption$avg_daily_screen_time_hours` → 1–10 h). `tests/testthat/test-<name>.R` asserts each numeric column equals `round(k * original)` / `k * original` / the documented rescale formula / (for exceptions) the original exactly; `test-reflavor-constants.R` asserts every `k` is finite and `≠ 1`. Run `devtools::test()` after touching `data-raw/reflavor_datasets.R` or `R/reflavor_constants.R`.
4. **Transforms live in one script.** `data-raw/reflavor_datasets.R` is the single source of truth — one block per dataset, loading the original `.rda`, transforming, and writing via `usethis::use_data(..., overwrite = TRUE)`. Extending Tier 2/3 means adding blocks here, a matching `R/<name>.R` doc file, and a matching test file, then running `devtools::document()`.
5. **Identifiable real-person data is out regardless of tier.** `trump_tweets` is **not** reflavored — it stays in the package unchanged for `dslabs` compatibility but the book does not use it (see its `@note`). Depersonalizing it (dropping identity + raw text) would leave nothing to teach text mining with, so instead the text-analysis chapter uses the externally hosted, permissively licensed **HC3** corpus (Human ChatGPT Comparison Corpus, Guo et al. 2023, arXiv:2301.07597, CC-BY-SA-4.0). HC3 is **not bundled** into `behdslabs` — students download it themselves — so the redistribution question stays with the upstream host. Decided 2026-09-08.

## Helper functions (light touch, not yet done)
- `rfalling_object()` — optional cosmetic rename to a "signal decay" framing (wearable battery/signal degradation). No data change. Archived-plan note: measurement error, analogous to noisy RT or biometric data from wearables.
- `fit_recommender_model()` — reframe example to pair with `app_ratings` once that exists (Tier 2). No logic change. Archived-plan note: the latent factors `p` (users) and `q` (items) are analogous to person scores and item loadings in factor analysis of preference data; the user-effect term `a` captures individual rating style (optimistic vs. critical), the same individual-difference control used in standardised UX questionnaires.

## How to extend this (Tier 2/3, or fixing Tier 1)

1. Add a block to `data-raw/reflavor_datasets.R`: load the original `.rda`, transform, `usethis::use_data(new_name, overwrite = TRUE)`.
2. **Choose and document a `k` for every numeric column that isn't an exception** (see ground rule 3): add it to `R/reflavor_constants.R`'s `.reflavor_k` list before writing the transform block, and grep both `behdsbook-part-1` and `behdsbook-part-2` for any chapter already using this dataset — every hard-coded axis range/break, reference-line/annotation coordinate, or numeric prose claim tied to it needs the same `k` applied in the same sweep (see `plan_forward.md`'s "Reflavoured-dataset literals move in lockstep" rule).
3. Add `R/<new_name>.R` with roxygen docs modeled on an existing Tier-1 file (e.g. `R/app_task_completion.R`) — include the `@note` disclaimer and state which columns are scaled by which `k` and which are kept as-is.
4. Run `devtools::document()` to regenerate `man/` and `NAMESPACE`.
5. Add `tests/testthat/test-<new_name>.R` asserting each column equals `round(k * original)` / `k * original` / the original exactly, per `helper-reflavor.R`'s `K` object (see any existing test file for the pattern).
6. Run `devtools::test()` then `devtools::check()` — both should stay clean (0 errors/warnings/notes).
7. Confirm `git diff --stat data/` shows only new files, or files whose numeric columns now differ from the `dslabs` originals by the documented `k` — never a file that's supposed to stay an unmodified passthrough, except the one-time multiplicative-rescale sweep (ground rule 3), which by design rewrites existing `data/*.rda`.

## Flagged value exceptions

These columns stay byte-identical to their `dslabs` originals for now, rather than getting a compliant `k ≠ 1` transform, because a naive multiplicative shift would break their meaning (a divide-pair denominator, a bounded percentage, a compositional total, an opaque matrix) and a proper fix needs a per-group design decision. Tracked as an open item in `PACKAGE_PLAN_DIARY.md`:

- `app_data_breaches$population`, `fitness_app_downloads_by_state$population`, `global_tech_adoption$active_user_base` — divide-pair denominators (their paired numerator — `incidents`, `downloads`, `gdp` — is scaled, so the derived rate/ratio already differs from the original; the denominator itself does not).
- `global_tech_adoption$app_uninstall_rate_per_1000` — kept as-is specifically to avoid re-deriving the logit-scale retention plots in `dataviz-principles.qmd` and `dataviz-in-practice.qmd`.
- `product_launch_forecast`/`product_launch_results`'s percentage columns (`raw_pref_*`, `adj_pref_*`, `adopt_*`) and `respondents` (a factor, not numeric); `ui_redesign_surveys`'s `prefer_*`/`undecided`/`margin` — bounded poll/survey percentages.
- `wearable_signal_profiles_by_cohort`'s 8 `pct_*` columns — compositional, must sum to ~100.
- `app_task_completion$completion_rate` — bounded [0,100] percentage (also the intentional silent-bug teaching example in `productivity/ai-assisted-coding.qmd`).
- `daily_mood_ratings`, `app_churn_prob$churn_prob` — a 1–7 Likert scale and a [0,1] probability, respectively.
- `gesture_swipe_data`/`gesture_swipe_data_3class`'s `x_1`/`x_2`, `sensor_activity_features$x`, `wearable_stress_signals$x` — opaque pixel/feature matrices.
